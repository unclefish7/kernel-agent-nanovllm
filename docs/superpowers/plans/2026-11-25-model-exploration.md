# 主动探查模型与单卡移植

目标是让 agent 对本地 Transformers 原生模型自行查证运算、生成一个 Python 候选，再由真实引擎与独立参照验收。首个用例选用已有、权重有限的 DeepSeek-V3 tiny。父仓库和 nano-vLLM 都使用 main。

1. 在 `nanovllm_selector/port/explore/` 实现按模块和符号读取源码、运行原生模型或 Python 探针、查看已保存的张量、逐项比较四种操作。保留每次调用、生成步、输入输出路径和数据类型，测试原地更新、多输出与漏采。
2. 在原有 ROCm 基础上补齐开发容器实际使用的依赖，每个执行任务使用私有临时容器。只读挂载模型、引擎和必要的项目代码。单次记录单独写入，探针、引擎和参照各自执行。宿主机负责 API 调用和记录。
3. 从现有移植入口启用工具调用。计算图可以作为额外材料。agent 可以按需阅读、取样、修订候选。保存工具记录、候选 Python 和报告至 `nanovllm_selector/outputs/`。
4. 用独立进程分别运行 nano-vLLM 候选与 Transformers 参照。在相同词元历史下比较多个长度的预填充和连续八步生成的完整词表分数，另用一段独立输入复验冻结的候选。
5. 对已验证模型运行回归，记录模型、权重、设备、两仓版本和实测边界。若存在引擎缺口，用原生实现和引擎入口复现后才补充引擎。按功能提交并同步 main。

## 实施结果

在线生成入口为 `nanovllm_selector.port.iterate --explore`，外部编码 agent 使用 `nanovllm_selector.port.explore --context` 与 `--tool`。两者调用同一套工具。宿主保存证据，独立进程核对完整词表，最终文件在双重验收后写入本次输出目录。

DeepSeek-V3 tiny 的 Codex 候选通过公开 12/12、跨页独立输入 10/10、两请求换序 16/16。已配置的 DeepSeek 生成后端公开最佳为 7/12。四个既有模型的冻结候选在引擎 `ba57abd` 上共通过 88/88 个位置。[五个模型的记录](../../../nanovllm_selector/README.md)
